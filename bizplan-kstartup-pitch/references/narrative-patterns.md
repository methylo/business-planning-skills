# narrative-patterns.md — 스토리라인 패턴 + 본문→피치 입력 매핑

## 1. 17장 기본 구조 (디바이더 4장 포함)

```
S1   L1 Cover           표지
S2   L2 Divider 01      Problem
S3   L3 Content         문제 정의
S4   L4 Number          문제 규모 (수치)
S5   L2 Divider 02      Solution
S6   L3 Content         솔루션 개요
S7   L3 Content         작동 방식
S8   L5 Compare         차별점 비교
S9   L2 Divider 03      Market & Strategy
S10  L3 Content         타깃 고객
S11  L4 Number          시장 규모 (TAM/SAM/SOM)
S12  L3 Content         진입 전략
S13  L4 Number          매출·수익 모델
S14  L5 Compare         자금 소요·조달
S15  L2 Divider 04      Team
S16  L6 Team            팀 구성
S17  L7 Closing         비전·CTA
```

현재 생성기는 17장 고정이다. 분량을 줄이려면 생성 후 별도로 편집하며, 자동 생성 계약에는 포함하지 않는다.

## 2. 사업계획서 본문 → 피치 입력 JSON 매핑

`bizplan-kstartup`의 12개 소항목을 피치 입력 JSON에 옮기는 편집 기준이다. `scripts/build-pitch.js`는 DOCX를 읽지 않으므로 실행 환경의 문서 읽기 기능으로 내용을 확인하고 `references/pitch-input-schema.md` 형식의 JSON을 먼저 작성한다.

| 본문 항목 | 피치덱 슬라이드 | 추출 규칙 |
| --- | --- | --- |
| 1-1 개발 동기·목적 | S3 문제 정의 (L3) | 본문 [문제 정의] 단락 → 글머리 3개로 분해 |
| 1-2 외부 환경 | (피치덱 생략) | 본문에만 포함, 피치덱 별도 슬라이드 없음 |
| 1-3 목표시장 | S10 타깃 고객 (L3) + S11 시장 규모 (L4) | [목표 고객 정의] → S10 / [시장 규모] 표 → S11 대형 숫자 |
| 2-1 현황 | (S6 일부 흡수) | 준비 수준 한 줄로 압축 → S6 마지막 글머리 |
| 2-2 실현 방안 | S6 솔루션 개요 (L3) + S7 작동 방식 (L3) | [핵심 기능 ①②③] → S6 본문 / [개발 단계] → S7 본문 |
| 2-3 차별화 | S8 차별점 비교 (L5) | [경쟁자 비교표] → 그대로 L5 표로 변환 |
| 3-1 자금 계획 | S14 자금 소요·조달 (L5) | [자금 소요·조달 표] → 그대로 L5 표로 변환 |
| 3-2 진입·성과 | S12 진입 전략 (L3) + S13 매출 (L4) | [진입 단계] → S12 글머리 / [매출 목표] → S13 대형 숫자 |
| 3-3 추진 일정 | (S12 일부 흡수) | 핵심 마일스톤 1줄 → S12 마지막 글머리 |
| 4-1 팀 현황 | S16 팀 구성 (L6) | [대표자] + [팀원] → 카드 1~4개로 변환 |
| 4-2 외부 협력 | (자동 변환 제외) | 필요한 내용은 사용자 확인 후 팀원 `career` 문구에 포함 |
| 4-3 인력 운용 | (피치덱 생략) | 본문에만 포함 |

### JSON 작성 절차

```text
1. 사업계획서의 PSST 12개 소항목을 읽는다.
2. 위 매핑표에 따라 필요한 문장·수치·표를 선택한다.
3. 선택한 내용을 pitch-input-schema.md의 필드에 넣는다.
4. 출처·단위·기준연도와 사용자 확인 상태를 점검한다.
5. 완성한 JSON을 build-pitch.js에 전달한다.
```

본문에만 남기는 항목과 인접 슬라이드에 요약하는 항목은 표의 규칙을 따른다. 자동 추출 함수는 이 패키지에 포함되어 있지 않다.

## 3. 스토리라인 패턴 (3종)

기본 17장의 4개 섹션 순서만 바꾸는 변형 패턴이다. 생성기는 슬라이드를 추가·삭제하거나 트랙션·기술 지표를 새로 만들지 않는다.

### 패턴 A — Problem-First

문제 → 솔루션 → 시장·전략 → 팀 순서다. 문제 근거를 먼저 설명해야 할 때 사용한다.

### 패턴 B — Team-First

팀 → 문제 → 솔루션 → 시장·전략 순서다. 팀의 실행 역량을 먼저 설명해야 할 때 사용한다.

### 패턴 C — Market & Strategy-First

시장·전략 → 문제 → 솔루션 → 팀 순서다. 시장 기회와 진입 계획을 먼저 설명해야 할 때 사용한다.

## 4. 패턴 선택 의사결정

```text
[질문 1] 팀의 실행 역량을 먼저 설명해야 하는가?
  YES → 패턴 B (Team-First)
  NO  → 다음 질문

[질문 2] 시장 기회와 진입 계획을 먼저 설명해야 하는가?
  YES → 패턴 C (Market & Strategy-First)
  NO  → 패턴 A (Problem-First)
```

3개 패턴 중 자동 추천 후 사용자 최종 선택을 받는다.
