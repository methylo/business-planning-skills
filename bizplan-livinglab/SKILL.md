# bizplan-livinglab

상주시 주민주도형 마을리빙랩 전용 작성 절차다. 다른 연도·지역·수행기관의 공모에는 공식 양식을 먼저 받아 항목과 예산 규칙을 다시 매핑한다.

## 참조 파일

- `references/template.md`: 상주시 양식 기반 빈칸 템플릿
- `references/sample-gongseong.md`: 공개용으로 비식별화한 가상 예시
- `examples/budget-example.json`: 산식 검증용 가상 예산

## 선행 조건

작성 전에 사용자가 제공한 해당 연도 공고문·신청서·예산편성지침을 확인한다. 다음 항목을 확인하지 못하면 `BLOCKED`로 표시하고 예산안을 확정하지 않는다.

- 사업명과 수행기관
- 보조율과 총사업비
- 허용·불허 비목
- 비목별 한도와 강사비 기준
- 제출 서식과 첨부 목록
- 사업 기간과 평가 기준

공식 공고와 이 스킬이 다르면 공식 공고를 우선한다.

## 절차

1. 일반현황: 마을명, 팀명, 주제, 기간, 사업비, 팀 구성을 받는다.
2. 문제인식: 지역 통계와 주민 문제를 출처와 함께 정리한다.
3. 실현가능성: 리빙랩 단계, 실험 장소·대상·방법·평가지표를 작성한다.
4. 이해관계자: 팀·협력기관·수혜자와 역할을 구분한다.
5. 확산·기대효과: 가치제안, 고객군, 연차별 로드맵을 작성한다.
6. 예산: 공식 지침의 비목과 한도를 적용하고 산식·소계·총계를 계산한다.
7. 전체 문서를 통합하고 사용자 확인을 받는다.

각 단계 후 초안을 제시하고 다음 단계 진입 여부를 확인한다. 사용자가 일괄 진행을 요청해도 확인되지 않은 사실은 자리표시자로 남긴다.

## 예산 검증

- 모든 항목은 `단가 × 수량 = 금액`으로 기록한다.
- 항목 금액의 합과 비목 소계가 일치해야 한다.
- 비목 소계의 합과 총사업비가 일치해야 한다.
- 비율 제한은 공식 예산편성지침에서 확인한 값만 적용한다.
- 세금·원천징수·부가세 포함 여부를 명시한다.
- 확인되지 않은 비목을 임의로 허용하지 않는다.

`examples/budget-example.json`은 계산 구조를 보여주는 가상 예시이며 실제 공고의 허용 기준이 아니다.

## 문체와 근거

- `~함·~임` 서술체를 사용한다.
- 한 문장에는 사실 또는 계획 하나만 담는다.
- 표·그림 번호는 문서 전체에서 연속으로 매긴다.
- 통계·지도·사례에는 출처와 기준연도를 표시한다.
- 실제 인명·계좌·연락처·상세 주소는 공개 샘플에 넣지 않는다.

## 출력

기본 산출물은 전체 구조를 갖춘 Markdown 초안이다. 실행 환경에 DOCX 생성 도구가 있으면 같은 내용을 `.docx`로 변환하고, 생성 후 표·쪽번호·글꼴·페이지 나눔을 확인한다. 문서 도구가 없으면 `.docx` 생성을 완료했다고 보고하지 않는다.

파일명:

```text
{마을명}_마을리빙랩_사업계획서_{YYMMDD}.md
{마을명}_마을리빙랩_사업계획서_{YYMMDD}.docx
```

## 완료 확인

- [ ] 해당 연도 공식 공고와 예산지침을 확인했다.
- [ ] 모든 수치와 사례에 출처가 있다.
- [ ] 예산 산식·소계·총계가 일치한다.
- [ ] 확인되지 않은 개인정보가 없다.
- [ ] 미확인 항목은 자리표시자로 남았다.
- [ ] DOCX를 만들었다면 실제 파일을 열어 구조를 확인했다.
